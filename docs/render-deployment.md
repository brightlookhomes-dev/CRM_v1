# Render Backend and PostgreSQL Deployment

This Blueprint creates a Render Free Node web service in Singapore and connects it to a Neon Free PostgreSQL database. It does not create Render resources until you connect the repository and apply the Blueprint. This is a $0 demo/testing setup, not a reliable production service: Render Free sleeps while idle, and Neon Free has strict usage limits.

## What the Blueprint configures

- `brightlook-api`: Node.js web service rooted at `backend`, built with `npm ci`, started with `npm start`, and health-checked at `/api/v1/health`.
- PostgreSQL is hosted by Neon Free in Singapore; its pooled connection URL is supplied as `DATABASE_URL`.
- The API runs migrations on startup. Render runs `npm run seed` once after the first successful deploy to create the initial admin.
- `JWT_SECRET` is generated by Render. The database URL, R2 credentials, and `SEED_ADMIN_PASSWORD` are entered as prompted secrets; they are not committed in `render.yaml`.

## Create the Neon database first

1. In Neon, create a project on the **Free** plan and choose the AWS Singapore region (`aws-ap-southeast-1`) if available.
2. Keep the default database and branch, and open **Connect** for the project.
3. Select the pooled connection option and copy the full connection string. It contains database credentials; keep it private and do not paste it in chat.
4. Confirm the Neon organization is still on the Free plan. Current limits include 1 GB Postgres storage per project, 100 compute-hours per month, and 5 GB public network transfer per month. Idle compute scales to zero after 5 minutes; data remains stored.

## Before applying

1. Ensure the latest backend, migration, Pages proxy, and `render.yaml` changes are committed and pushed to `brightlookhomes-dev/CRM_v1` on `main`.
2. In Render, choose **New → Blueprint** and connect `brightlookhomes-dev/CRM_v1`.
3. Select the `main` branch and let Render find the root `render.yaml`.
4. Confirm the Blueprint shows one **Free** web service and no Render database. Review the price before clicking **Apply**; it should show `$0/month` for the Render service.
5. When prompted, enter:
   - `DATABASE_URL`: the Neon pooled connection string. Include the `sslmode=require` query parameter if the copied URL does not already have it.
   - `SEED_ADMIN_PASSWORD`: a new, unique production admin password.
   - `R2_ACCOUNT_ID`: your Cloudflare account ID.
   - `R2_BUCKET`: `brightlook-crm-media`.
   - `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY`: the bucket-scoped R2 token values.

   Enter secrets only in Render's form. Do not put them in the repository or chat. If Render does not prompt for one because the Blueprint already exists, add it from the API service's **Environment** page and redeploy.

## First deployment and checks

1. Wait for `brightlook-api` to become available. On startup, the service runs database migrations; the initial deploy hook creates the admin account once.
2. Open the API service's **Logs** and confirm it reports `database: postgres` and is listening on Render's port.
3. Open `https://<render-service-name>.onrender.com/api/v1/health`; expect `{"success":true,"message":"OK"}`.
4. Sign in with the admin username `admin` and the `SEED_ADMIN_PASSWORD` you entered. Do not run the demo seed in production.
5. Upload an allowed image or PDF. Confirm the object is in the private R2 bucket and the app can view it through the API. Test permanent deletion and confirm the R2 object disappears; failed deletes are retried from the PostgreSQL cleanup queue.

## Connect `api.brightlookhomes.in`

1. In the Render API service, open **Settings → Custom Domains → Add Custom Domain**, and enter `api.brightlookhomes.in`.
2. In Cloudflare DNS, add the record Render specifies for that custom domain. Start with **DNS only** while Render provisions TLS.
3. Wait for Render to show the domain as verified and HTTPS active; then test `https://api.brightlookhomes.in/api/v1/health`.
4. Leave the existing `app.brightlookhomes.in` GitHub Pages DNS unchanged until the new frontend has been tested. For Cloudflare Pages, set `API_ORIGIN=https://api.brightlookhomes.in` and keep `VITE_API_BASE_URL=/api/v1`; the Pages Function proxies API requests same-origin.

## Important operational notes

- Keep `DATABASE_URL` set to the Neon pooled connection string, including `sslmode=require`.
- Neon Free is not an always-on production database: it is limited to 1 GB storage, 100 CU-hours, and 5 GB public egress per month, with no production SLA or scheduled backups. Exceeding compute/transfer limits suspends compute until reset; storage above 1 GB blocks writes. Keep independent backups before storing important data.
- Render Free web services spin down after 15 minutes without inbound traffic and can take about a minute to wake. They have 750 instance-hours per workspace per month and ephemeral filesystems. R2 is the persistent media store, but the API may be temporarily unavailable while waking.
- Render Free services are intended for previews and testing, not production applications. Use a paid always-on API and managed database before relying on this CRM for business operations.
- The API uses R2 for file bytes. Render's filesystem is not the permanent media store.
